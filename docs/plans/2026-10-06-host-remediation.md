# Host Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make host firewall startup, Nebula reloads, interrupted k3s installation, AppArmor ownership, multi-architecture lab reloads, and Mac mode/seed behavior safe and testable without replacing the existing deployment architecture.

**Architecture:** Keep `install.sh` authoritative for the host and regenerate the Console's `join.sh` with `make join`; Mac's build plugin embeds that same installer. Add behavioral shell-stub tests beside the existing join tests, disposable systemd integration for ordering, and Swift tests for Mac behavior. Preserve identities and host-owned configuration, and fail closed when a critical host policy cannot be installed or published.

**Tech Stack:** Bash, systemd, iptables, AppArmor, Go `testing` with shell stubs, k3s installer, Swift Testing, Virtualization.framework, cloud-init NoCloud.

### Task H6a — F15 (medium): Publish Mac mode only after durable write

**Files:** Modify `mac/WeCoLabCore/NodeVM.swift:31-38,63-74`, `mac/WeCoLab/WeCoLabApp.swift:86-116`, `mac/wecolab-node/main.swift:49-76`; test `mac/Tests/CoreTests.swift` (new mode-publication cases); update `mac/README.md:126-147`.

- [ ] Write a Swift Testing case using a **proposed injectable mode writer** (package-internal closure or tiny value dependency on `NodeVM`, defaulting to `Data.write(options: .atomic)`), so a failed write can be forced deterministically without starting a real VM. Assert same-state retry invokes writer again and `mode` remains the last successfully written state, not desired state; successful second attempt publishes `mode` once. Test idle-to-active failure when stale on-disk `idle` exists: the node agent must not see idle as valid after the failure; if invalidation/removal fails, the VM must not continue claiming workload eligibility. Also assert an idle write failure cannot falsely clear the node's idle taint. No sleep, real input-event injection or string inspection is needed.
- [ ] Replace silent `try?` and pre-write assignment with a testable publication operation. Before an idle-to-active transition, invalidate the stale idle file and invalidate the cached publication state; if this fails, stop the VM and report failure. Then write the desired mode atomically and cache it only after success. This ensures that a failed active write followed by a return to idle also republishes idle instead of incorrectly skipping it because of the old cache. Surface errors in the app and CLI, retry recoverable failures, and preserve balloon behavior, the five-second cadence and the node-agent taint contract. A failed publication must not masquerade as success.

Mode publication contract (extract the write into a package-internal test seam rather than requiring `VZVirtualMachine` in unit tests):

```swift
// Only the successful durable publication may change the cached mode.
try writeMode(Data(next.utf8), to: modeURL)
mode = next
```

Provide an injectable temporary `modeURL` and writer so tests never touch `Paths.user.share`; test invalidation/stop decisions without Virtualization.framework objects. An absent mode file uses the node agent's existing non-idle backstop. Cover idle-to-active failure followed both by another active tick and by a return to idle; each must converge from actual publication state, not a stale cached value.

Expected deterministic write-fail/retry, stale-idle failure safety, and observable app/CLI errors. Then run `cd mac && swift test` after H6b; macOS 27 seed behavior is **not** assumed fixed by this mode change.
