Storage

A project's vault is the bucket its databases archive to, with Object Lock so nobody can delete a backup. Only databases are replicated and backed up. Volumes are site-local: each site has its own, and files on them do not follow the app when its primary moves.

Deploy an app

Pick an app from the catalog, or give a container image. The Console writes the app to the Fabric; each chosen site runs its part within a minute or two.

Catalog

From the HomelabOS catalog, validated there; translated mechanically into a workload, a replicated database when it has Postgres, sidecars, and a volume per data path. Volume data stays at the site that holds it; database data is replicated and backed up.
Postgres, replicated, backed upPublish on the mesh

What gets created

  • 1Deployment and Service in the project, placed on every chosen site.
  • 2With Postgres: a cluster per site, primary at the primary, replica fed from the vault, nightly backups, first one immediately.
  • 3A Door route for the hostname with a certificate, following the primary.
  • 4The App with its gates. Ready when every gate is green.
ⓘThe app reads its database settings from the database's own secret at its site. Pods run in user namespaces: root inside the container is an unprivileged user on the box.

Add a site

A site is one cluster at one place. Create it here, then run one command on its first box. A collaborator's site joins the same way, with their project as owner.

Your SSH keys

root's authorized keys on every box of the sites your projects own (admins: every box); boxes pick them up within the hour

New site

Then, on the box

  • 1Create the site here. Its join command is shown once and works once, for a day.
  • 2Run it as root on the site's first box: Ubuntu 24.04 or Debian 13, amd64 or arm64. Nothing needs to be opened on its router.
  • 3About five minutes: Nebula, k3s, its copy of the Fabric, then everything else from it.
  • 4The site turns Ready in Sites when its Warden answers. More boxes join it from its card there.
